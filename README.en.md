## Single repository (migration in progress since November 2026)

This repository is being turned into a single repository for the whole atlas: the code, source material and base data of the original eight volumes have moved in, the new Qin and Han volume was compiled here directly, and the unified data format, global gazetteer, shared projection and terrain, unified territory engine and the hub's timeline mode will all be built here. Steps and progress are in section 19 of the style guide (历史形势图统一规范). Each volume's old repository and address are kept as the old edition and no longer change.

```
lidai-yutu/
├── run.py                 build entry point
├── requirements.txt       dependencies shared by all volumes
├── requirements-lock.txt  versions that reproduce the published pages byte for byte
├── hub/index.html         source of the hub page
├── eras/<slug>/           each volume: content/ sources, src/ stage-1 build code, tools/, run.py; era.toml describes the volume;
│                          source.json the stage-1 output (the data source); engine.json the territory from the unified engine; short.tsv timeline short titles
├── core/v1/               unified data format v1: spec FORMAT.md (in Chinese), legacy conversion, global-table generation, step-3 corrections
├── core/web/              unified front end: builds each volume's new page from v1 (the template all nine volumes share, timeline, deep links); see core/web/README.md (in Chinese)
├── core/geo/              unified projection, world base map, terrain relief: all parameters in config.toml; see core/geo/README.md (in Chinese)
├── core/engine/           unified territory engine (it draws the territory of all nine volumes): parameters gathered in config.toml; see core/engine/README.md (in Chinese)
├── global/                global tables: places, polities, physical features, glossary; palette.toml the shared palette; walls.toml border walls; decisions.toml manual decisions; review/ lists to review
├── geodata/               one copy of the base data (ne/, etopo20/, prov/, derived/); each volume's geodata/ holds symlinks to it;
│                          relief/<slug>/ each volume's relief images, world/<slug>.json the world land outside each volume (made by core/geo, committed)
├── tools/thumbs.py        hub thumbnails
├── tools/colorcheck.py    palette survey: colour difference between neighbouring polities in every volume
├── tools/palette.py       colours for new polities: picks from the low-saturation palette based on its neighbours in the unified engine's territory
└── docs/                  published by GitHub Pages: index.html is the hub, <slug>/index.html each volume
```

A volume's slug is its old repository name without `-map`: chunqiu, zhanguo, hanmosanguo, liangjin-nanbeichao, suitang, tangsong, songyuan, minguo-xinzhongguo; the Qin and Han volume has no old repository and its slug is qinhan. The build has three stages: each volume's own build script (`eras/<slug>/run.py`) produces the ownership, text, entries and base map and saves them as `eras/<slug>/source.json` (committed; no territory or colours); from these the global tables are rebuilt, the data converted to v1 and the step-3 corrections applied; and the new pages `docs/<slug>/index.html` are generated from v1, with the terrain relief and world base map pre-generated in `geodata/relief/` and `geodata/world/` merged in. Territory comes from the unified territory engine, computed from the ownership in the v1 data: for the eight volumes other than Qin and Han (`geometry = "engine"` under `[engine]` in `era.toml`) it is saved as `eras/<slug>/engine.json` (committed) and merged into the v1 data when that is generated, and `python run.py` recomputes it automatically when it builds those volumes; the Qin and Han volume builds in two passes, its own stage 1 merging the engine's territory into `source.json`. Colours all come from `global/palette.toml`.

```bash
pip install -r requirements.txt
python run.py                    # build all nine volumes: each volume's stage 1 → territory → v1 data → new pages, then update the hub
python run.py zhanguo songyuan   # build only these volumes
python run.py --html             # each volume's stage 1 only reassembles; no territory computation (needs one full build first)
python run.py --web              # no territory computation: rebuild the global tables, v1 data and new pages from each volume's source.json and engine.json (use this after changing short titles, translations, colours or content corrections; after changing seed coordinates or ownership, rebuild the volume)
python run.py --geo              # regenerate the terrain relief and world base map, then the new pages (after changing projection, tiers or base-map settings in core/geo/config.toml; the first run downloads the ~42 MB relief source)
python run.py --v1               # only rebuild the global tables and each volume's v1 bundle (build/v1/, not tracked)
python run.py --hub              # only update the hub
python run.py --check            # check whether docs/ and each volume's engine.json were built from the current data
python run.py --list             # list the volume slugs
```

GitHub Pages publishes from the `/docs` folder of the `main` branch.

All nine volumes now take their colours from [`global/palette.toml`](global/palette.toml), keyed by each polity's global ID, so a polity has the same colour in every volume. The main dynasties take the colour of their phase in the Five Phases cycle, in a light, low-saturation form: Qin (Water) black, the two Han dynasties, Sui and Song (Fire) red, with Shu Han, heir to Han, a shade lighter; Xin, Cao Wei and Tang (Earth) yellow; Jin (Metal) white. The other polities were recoloured where needed so that no two neighbouring territories in any snapshot clash. The Republican volume keeps its colours, except for the Netherlands, the Tibetan government and Afghanistan, which could not be told apart from British territory. Every polity has its colour set in the file, and the build stops if one is missing; for a new polity, run `python tools/palette.py`, which picks a colour based on the polity's neighbours in the territory computed by the unified engine (`--write` adds it to the file), then `python run.py --web`. After changing colours, rerun `python3 tools/colorcheck.py` (after `python run.py --web` or `--v1`) and regenerate the hub thumbnails.

The Great Desert (Gobi) in seven volumes used to take its extent from the "GOBI DESERT" label area in Natural Earth's geographic regions, which also covered the steppe north of the Yin Mountains, the Hexi Corridor and the Kherlen River. It is now redrawn by [`tools/damo.py`](tools/damo.py) from the three Gobi ecoregions of RESOLVE Ecoregions 2017 (data in [`geodata/resolve/`](geodata/resolve/README.md), CC-BY 4.0), leaving out the steppe south of the desert (its central stretch ends where the *New Book of Tang* geography treatise has the road enter the desert, at about 43°N), the Hexi Corridor and the Juyan oasis, and the land north of the southern foothills of the Khangai Mountains; the Qin and Han volume and the Late Han volume also leave out the Han farmland in the northern Ulan Buh Desert. For Juyan, the Republican volume leaves out only today's Ejin oasis and draws the ancient Juyan oasis of Han to Yuan times (around Khara-Khoto) as desert; the other volumes leave out both. The new outline replaces the old one in every volume when the v1 data are generated (`core/v1/overlay.py`). At the scale of these maps the Gobi itself shows no visible change over two thousand years; what changed were the sandy lands and oases. The extents of three sandy lands are drawn by hand for each volume in [`tools/sands.py`](tools/sands.py), with the sources given at the top of the file: the Mu Us (Tang–Song, Song–Yuan and Republican volumes), the Horqin (Song–Yuan and Republic) and the Kubuqi (Republic). The script writes `geodata/derived/sands.json`, and the extents replace the volumes' own by global ID when the v1 data are generated.

The first batch of the architecture cleanup (20 November 2026) merges the page templates of the seven volumes from Qin and Han to the Republic into one, [`core/web/template.html`](core/web/template.html) (there were seven, differing from one another by anywhere from two or three hundred to over five hundred lines). A layer is drawn whenever a volume has data for it, and what differs from volume to volume (the text and a few switches, such as the time unit and how hatching is drawn) is set in the `[web]` section of each volume's `era.toml`; `core/web/patch.py` is now used only by the Spring and Autumn and Warring States volumes. During the merge a script compared each volume's old and new pages, stepping through every snapshot, both colorings, each view, zooming, clicking through each group of the index, the legend switches, hovering and clicking on the map, search, keyboard controls, the chronology, the gazetteer, the English interface, deep links, dark mode and a narrow screen, and comparing the DOM after each step; it also compared screenshots pixel by pixel in several states. The old and new pages differ only in a few places that were deliberately made consistent: when the current period lasts only one year, only that year is shown; in a snapshot's notes, the label "Campaign" appears only once for all of the current period's routes; campaign routes are drawn and their names placed the same way in every volume, selecting a route fits the whole route into view (jumping, if it is not in the current period, to the snapshot where it ends), and selecting a route's entry in the index lists every stop along the way; the year a canal was dug is also shown in the index; roads in the Republican volume are drawn like the ancient roads of the Late Han volume; and capital moves in the chronology all give the state and its new capital. A few old faults were fixed at the same time: the zoom on selecting a prefecture was occasionally wrong (the prefecture's serial number was mistakenly used to look up an entry's category); in the Qin and Han volume, the dates of the peoples in the gazetteer were shown as month indices, and a deep link giving a year without a month opened the year before; and the playback-speed button's tooltip stayed in Chinese in the English interface. The Qin and Han volume still draws its long walls and imperial highways beneath the canals (`lines_under_canal` in `[web]`).

The second batch of the architecture cleanup (20 November 2026) gives the Spring and Autumn and Warring States volumes the same "point → unit → polity" structure in the v1 data as the other seven, so v1 now has a single form (format version 2; `model` is gone from each volume's `era.toml`). The seeds the two volumes share, `content/seeds.txt`, now go into their v1 `places`: they are used only to compute territory, are not drawn on the pages, and are kept out of the global place table for now (the two volumes' cities still enter it as entries). Each snapshot records which state each seed belongs to (`own`) and which polity each state belongs to (`pol`). In the Spring and Autumn volume the polity level is the suzerain: states that acknowledge Zhou belong to the polity Zhou, so the Zhou realm drawn in Suzerain coloring is the territory of the polity Zhou. The unified territory engine used to need separate code to read these two volumes; now all nine take the same path. Checks: with unit numbers mapped back to state names, the engine's input matches the old input item for item, and the territories it computes have the same shapes; only some boundary rings start at a different vertex or come in a different order, because the engine now identifies units by index rather than by state name. The global tables are unchanged, the other seven volumes' pages are unchanged byte for byte (their v1 data differ only in the format version and the dropped `model` field), and the two volumes' pages were compared pixel by pixel in 100 page states (Spring and Autumn) and 106 (Warring States) with no visible difference. The two volumes still use the Warring States-style template; moving them to the shared template will be a separate batch, in which sample pages come first and the drawing style is settled from them. Their cities' ownership history (which state holds a city from which year) was derived by the old build from its old partition grid, and will be redone when the old territory computation is retired.

The first half of the third batch of the architecture cleanup (20 November 2026) prepares to retire the territory that each volume's old build computes in stage 1 (a raster partition). That territory has long been absent from the pages, but four things still used it; each has now been replaced. First, colours: polities not listed in `global/palette.toml` used to take their colours from each volume's old build, which in the Qin and Han, Jin, Song–Yuan and Republican volumes picked them greedily according to which old territories bordered each other; now all 1,167 polities in the nine volumes have their colours set in the file (688 of them newly added, with the colours they already had on the published pages). Second, the Sixteen Prefectures of Yan and Yun in the Tang–Song and Song–Yuan volumes: the outline, the line between the prefectures south and north of the mountains, and the labels used to be derived from the old build's grid and did not line up with the engine-drawn borders on the page; now the unified territory engine derives them from its partition at the first snapshot in which the region appears (the member seeds are listed in `m` in the v1 `base.regions`), so they now coincide with the borders. Third, in the Spring and Autumn and Warring States volumes, the ownership history of cities, passes, battles and commanderies (which state holds each in a given snapshot; commanderies also use it to decide when to appear) used to come from the old partition: each place took the history of the seed whose cell it fell in. Deriving it from the engine's partition would change the owner of 24 entries in some snapshots, some for the better (Yu's capital, which the old build gave to Guo) and some for the worse (Zhu's capital would go to Lu in 46 snapshots); so the seed each place falls under is frozen in each volume's `content/links.txt`, the ownership history still follows that seed in `seeds.txt`, and the pages are unchanged. Fourth, in the Qin and Han volume, which Qin commandery each place belongs to used to be decided from the commandery boundaries drawn by the Warring States volume's old build; it is now frozen in `eras/qinhan/content/qinjun.py`. Checks: on the Tang–Song and Song–Yuan pages only the Sixteen Prefectures changed, and the other seven pages are byte-for-byte unchanged. Stage 1 of all nine volumes was then rerun with the edge weights of the old build's shortest-path search multiplied by random factors, which changed the old territory a great deal. All nine pages still came out byte-for-byte the same as without this perturbation, showing that the pages no longer depend on the old territory. The second half of the batch will make stage 1 output only ownership, text and entries, and remove the old build's territory computation.

The second half of the third batch of the architecture cleanup (21 November 2026) reduces each volume's stage 1 to writing `eras/<slug>/source.json`: the GEO and DATA blocks that were embedded in the old pages, minus the territory geometry (the territory rings and labels of each snapshot, the geometry pool, the outline of the Sixteen Prefectures) and the territory colours, with one line per key and per element so that diffs are easy to read. The Qin and Han volume is the exception: its stage 1 already merges in the engine's territory and the two junction snapshots, so its source.json keeps the geometry. The repository converts source.json into v1, fills in the territory from each volume's `engine.json` and the colours from `global/palette.toml`; `legacy.html` is no longer produced, and the nine existing copies have been deleted. Removed with them: each volume's old territory computation (grid, travel cost, multi-source shortest paths, border tracing, merging) and greedy colouring; each volume's page template, territory sketches and screenshot tools; the copies of ETOPO20 that only the cost grids used; the colours in each volume's `content/` (`col`, `STATE_COLORS`, the Tang–Song volume's `colors.lock.json`); the Jin volume's `tools/junction.py`, which extracted the junction data; the Republican volume's `tools/verify.py`, which checked seeds against the old territory; `core/engine/regress.py` and `python run.py --engine` (the comparison with the old engines); and each volume's `requirements.txt` (all dependencies are in the root one). The Spring and Autumn and Warring States pages still use the Warring-States-style old template, which moves from the two volumes' `src/template.html` to `core/web/old/`. The Jin volume still sets the ownership in 280 and 581 from two frozen sets of the neighbouring volumes' territory rings (`geodata/junction_*.json`). The Qin and Han volume's stage 1 now reads the source.json and engine.json of the Warring States and Late Han volumes (stopping if they are missing, instead of falling back to the old geometry), and the root `run.py` runs it after every other volume's stage 1. A first build from a fresh clone used to fail, and rebuilding a volume after its ownership changed could also stop; three things were fixed: (1) when a junction snapshot looks up the other volume's polity list, it used to read that volume's v1 in `build/v1/` (which a fresh clone does not have yet) and now converts it from that volume's source.json; (2) in the pass that produces ownership for the engine before the territory is recomputed (`--lenient`), the Qin and Han volume's first pass and any volume whose ownership has just changed have no territory yet, and the global tables merged polities of the same name according to the snapshots in which they had territory, so Qin, Han and others were not merged, their global IDs changed and the build stopped when their colours could not be found — presence at a snapshot is now judged from ownership (independent of territory; the global tables come out byte-for-byte as before); and (3) the Qin and Han volume's first pass (the root `run.py` passes `--first`) no longer reads the neighbouring volumes' territory, whose engine.json may still be from an earlier run and not match the source.json they have just written. Checks: all nine source.json files are byte-for-byte the same as those split out of the first half's legacy.html, the eight engine.json files are byte-for-byte unchanged, the nine pages and the hub are unchanged byte for byte, and of the generated files in `global/` only one sentence at the top of the corrections list changes; `python core/v1/roundtrip.py` is lossless for all nine; and a copy holding only the tracked files builds in one go with `python run.py`. Stage-1 times per volume (same machine, old → new, seconds): Spring and Autumn 60 → 1, Warring States 29 → 1, Qin and Han 32 → 12, Late Han 20 → 0.4, Jin 87 → 2, Sui–Tang 39 → 2, Tang–Song 63 → 2, Song–Yuan 205 → 46, Republic 792 → 37, about 22 minutes → 1.7 minutes in all; computing the territory with the unified engine takes about 13 minutes more (about 7 for the Republic, about 2 each for Jin and Song–Yuan), so a full build of all nine volumes takes about 16.5 minutes.

The fourth batch of the architecture cleanup (21 November 2026) deals with the five snapshots that two neighbouring volumes share (212 BC, AD 184, 280, 581 and 979). In each, the volume that is not authoritative copies the other volume's territory inside the other's computed area, but its points kept their own allegiances, so some tooltips named one owner while the map drew the point inside another (for example Xingcheng (Fangzhou) in the Jin volume's 280 snapshot, and more than twenty towns in Qin commanderies in the Qin and Han volume's 212 BC snapshot). Now, when the v1 data are generated, every point inside the other volume's computed area at such a snapshot is given to the drawn unit that contains it; a point lying on a border (within 0.01° of a unit) goes to the nearest unit, keeping its original unit if that is equally near; and a point on blank land, more than 0.01° from every unit, belongs to no one. The volume's original allegiances are kept in the snapshot's `own_src`, which is what the unified engine reads, so neither the territory nor the engine results change. In all, 69 points change allegiance across the five snapshots: 31 prefectures, commandery seats and towns shown on the pages, and 38 reference points used only in the computation. The Jin volume used to derive its allegiances in 280 and 581 from two frozen sets of the neighbouring volumes' old territory rings (`geodata/junction_*.json`), according to which ring each point fell in; the result is now written point by point in `content/junction.py` and the two json files have been deleted; the outcome is the same. The original plan to recompute each junction snapshot jointly (rerunning it in one volume's engine under the other volume's rules) has been dropped: by measurement, the territories of the polities the two volumes share already overlap at 1.00 at every junction (the lowest is the Kara-Khanid Khanate in 979, at 0.994), and a joint recomputation would struggle to match that. Checks: only the `own` arrays of the junction snapshots change, on the Qin and Han, Jin and Tang–Song pages; everything else on those three pages, the other six pages, the hub, the global tables and the eight engine.json files are unchanged byte for byte.

The fifth batch of the architecture cleanup (21 November 2026) moves the last settings and rule files that the unified territory engine still read from the individual volumes into the source material, `era.toml` and the global tables. From now on the engine reads only `[engine]` in `era.toml`, the v1 data, the global tables, and two kinds of source material in each volume (the hand-drawn outer edge and each point's reach multiplier). First, reach multipliers: the Late Han build used to convert each point's partition radius and write the result to `build/reach.txt` on every run; the converted values are now written point by point in `content/seeds.py` (`R=`, with defaults by type). The Qin and Han volume already kept its values in `content/seeds.py`; the engine now reads them directly there too, without the build copying them out. Second, border walls: the modern border stretches not used as walls, the time-limited stretches and the hand-drawn historical lines move from the Republican volume's `src/config.py` to the global table [`global/walls.toml`](global/walls.toml), which the future Yuan–Ming and Qing volumes will also draw on; Europe and Africa, which are cut out of the computed area, go under `[engine]` in the Republican volume's `era.toml` (`exclude`), and the engine and the volume's stage 1 read the same copy. Third, subdivisions: the provinces of each Late Han point under Wei, Jin and Wu are written in `content/seeds.py` (`wei`, `jin`, `wu`); stage 1 works out each point's province block at every snapshot and writes it into `source.json` (the snapshot's `zn`, the v1 snapshot's `zone`), the engine partitions by it, and `src/zhou.py` is deleted. The three settings for subdividing Qin into commanderies in the Warring States volume go into `era.toml` (`sub.unit`, `sub.hosts`, `sub.near`), the seats are taken from the volume's Qin commandery entries (`sub.seats`), and `src/jun.py` is deleted. Fourth, colours: the new [`tools/palette.py`](tools/palette.py) picks a colour for any polity that has none in `global/palette.toml`, based on its neighbours in the territory computed by the unified engine, and `--write` adds it to the file; the full build still stops when a colour is missing, and now points to the tool. It was tested by deleting the colours of three existing polities (the Southern Liang, the Western Liao and the abandoned Jiang–Huai lands): for each, the smallest colour difference between the picked colour and its neighbours' colours is no lower than with the original, hand-picked colour. The engine's input fingerprint is also completed: it used to leave out the reach multipliers, the border walls and the areas cut out of the computed area, so changing them went unnoticed by `--check`; the outer edge and the subdivisions were hashed by file bytes, and now everything is hashed from the data read, so editing a comment no longer forces a recomputation. The engine also no longer goes through Python's bytecode cache when it reads source files (the cache can go wrong when a file is changed and changed back within the same second without its size changing). Checks: the nine pages, the hub and the global tables (apart from the new `walls.toml` and one comment line at the top of `palette.toml`) are byte-identical, only the fingerprints change in the eight `engine.json` files, and every input the engine reads is the same as before; the Late Han `source.json` only gains each snapshot's province blocks.

The sixth batch of the architecture cleanup (25 November 2026) moves the Spring and Autumn and Warring States volumes onto the unified template as well, [`core/web/template.html`](core/web/template.html), so all nine volumes now share one page template; the Warring-States-style old template `core/web/old/` and `core/web/patch.py`, which gave it the shared shell, are deleted (the shared shell and the relief opacity that `patch.py` still supplied move into `assemble.py`). `legacy.from_v1` turns the two volumes' v1 back into the Warring States layout, and the new `core/web/simple.py` converts that into the layout the unified template reads: states and Rong and Di peoples become units, major cities and towns become places (the allegiance at each snapshot is carried forward from the entry's allegiance changes), and events, long walls and highways, canals, Qin commanderies, the falls of states and the grounds for Zhou allegiance all come along; territories, allegiances, entries, notes and English are unchanged. What only these two volumes have is added to the unified template, again drawn only when a volume has the data: BC years, several labels for one state, Qin commanderies (boundaries and seats, with their own group in the index and gazetteer), towns (small gray dots, with their own group), the falls of states and the building of walls and highways in the chronology, and long walls faded once abandoned; a volume with only one coloring gets no coloring buttons (Warring States), and in the Spring and Autumn volume the States coloring gives every state its own color without the heavy Zhou-realm line, with hatching drawn only in Suzerain coloring; as in the other volumes, what differs is set in `[web]` in `era.toml`. ## Adding a volume

The steps below edit `hub/index.html`; afterwards run `python run.py --hub` to update `docs/index.html`, the published copy.

1. Copy an `<li class="juan">` block, put it into the contents in date order, and renumber the volumes (卷一, 卷二 …; Volume I, Volume II …).
2. Change these:
   - `id`
   - `data-short`, `data-short-en`: the short Chinese and English names shown on the timeline
   - `data-start`, `data-end`: first and last year
3. Change the link and the thumbnail (see the next section), and both language versions of the title, years, subtitle, description, `stats` and the thumbnail caption `thumb-cap`. Take the English from that map's own English title, subtitle and terms.
4. Add an `--m-xx` to `:root` and to both dark blocks as the volume's main color, one light and one dark value, and write `style="--c:var(--m-xx)"` on the `<li>`. The color should stand apart from its neighbors on the timeline.
5. Update the cover's 「凡八卷 · 前770 — 1954」 and "Eight volumes · 770 BC – 1954", the contents heading 「已成八卷」 and "Eight volumes completed", and the volume names in `<meta name="description">`, in `og:description` and in `DESC` in the script at the end of the page.
6. If the new volume falls outside 800 BC – 1960, change `R0`, `R1` and `TICKS` in the script at the end of the page, and the year range in the Timeline heading. The dynasty and period bands `BANDS` are in the same place (the Ming, Qing, Republic of China and People's Republic of China bands were added with the Republican volume).

The timeline needs no other change: it draws each volume's bar straight from that volume's `data-start` / `data-end`. Where volume names crowd together, each name goes on the lowest row that has room for it, and the timeline grows taller to match; a name at either end of the timeline (such as the Republican volume's) is moved inward so that it stays inside.

## Generating thumbnails

`tools/thumbs.py` reads the GEO / DATA embedded in a map's own `index.html` and, using that map's projection and palette, redraws one time node as a 360×270 image. It uses only the Python 3 standard library.

It handles three data layouts (all nine pages now use the layered layout):

- Tang–Song: nodes hold `z` / `p` / `pol`; units of kind `tribe` are drawn pale and dashed, as on the map. Since 25 November 2026 the Spring and Autumn and Warring States pages use this layout too, where a state may have several label points; for these two, `--flat` fills each state flat without polity outlines, as in their earlier thumbnails.
- Late Han, Jin, Sui–Tang and Song–Yuan: territory geometry sits in the shared pool `GEO.pool`. Nodes in the Jin map may also carry `kd` (a change of unit kind at that node, as when Goguryeo is drawn as a state rather than a tribe from 313) and `col` (light and dark colors overriding the unit's own at that node); the thumbnail follows what the node records.
- Republican: nodes are monthly, `t` holds a month index (year × 12 + month − 1) and the title is in `ti`; the projection center comes from `GEO.proj`, and the opening node `GEO.first` is also a month index. The caption gives the date as year.month, e.g. 1937.12.

Labels are drawn in two sets:

- Chinese labels use the state names of that year: for the Spring and Autumn and Warring States maps, the node's period alias `lab` first (such as 鲜虞 before 506 BC), then the state's name, without anything in parentheses.
- English is taken from the map's data. For the Spring and Autumn and Warring States maps (`--flat`) it is the node's period alias `labe`, or else the state's English name `ne`. For the other maps it is, in order of preference, the node's period alias `labe`, the unit's short map name `se`, or its full name `ne`, with anything in parentheses removed.
- English labels are spaced by estimated text width, long names break onto two lines at a space, and a name that will not fit is left out.
- Chinese label size follows the size of the territory, and a label is not allowed to run much wider than its territory: a state made up of several units used to get at least 15px, and now shrinks to fit when that is too wide (in the Republican volume many small states are made up of several units, which is why Puppet Mengjiang and the CPC border regions were drawn too large). `--zh` can switch to a short name and `--fs` can set the size; see below.
- Labels sit at the map's own label points. The unified engine finds each label point over the whole territory (the point farthest from its border), so for a large state that point often falls outside the thumbnail frame and the label is left out. For units given with `--inframe`, a label point outside the frame is moved into the part of the territory inside the frame, to the spot farthest from both the territory's border and the frame edge (Tibet in the Tang–Song volume, the Tibetan tribes in the Song–Yuan volume). This is off by default: turned on for every unit, it would add many small labels crowded along the frame edges.
- For a map that has no English yet, `--en "id=English name;…"` supplies the English thumbnail labels (keyed by unit id); these also take precedence over the map's own English names.

```bash
python3 tools/thumbs.py docs/songyuan/index.html --id sy --year 1120 --mode pol --out thumbs
```

It writes three files:

- `thumbs/thumb-sy.svg`: paste it into that volume's `.thumb-in`.
- `thumbs/thumb-sy.css.txt`: two lines of color tokens. Paste the light line into `:root` and the dark line into both dark blocks, next to the existing `/* 缩略图 zg */` and the others.
- `thumbs/thumb-sy.cap.txt`: the node's year and its Chinese and English titles, for writing the thumbnail caption `thumb-cap`.

Options:

- `--id`: a two- or three-letter code, used as the color-token prefix and clipPath id. Each volume needs its own.
- `--year`: which year's node to draw.
- `--node`: pick the node by index, counting from 0. Use it when one year has several nodes, as in the Sui–Tang map, which has month-level nodes.
- `--month YEAR.MONTH`: pick the node by year and month, for maps with monthly nodes such as the Republican map, e.g. `--month 1937.12`.
- With none of `--year`, `--month` or `--node`, the tool takes the node the map opens on (`GEO.first` holds a year or a month index, `DATA.first` an index), or else the first node.
- `--box W E S N`: the longitude/latitude frame. Without it the tool uses the map's view cn or all (`WEB.fits`).
- `--mode zhen|pol`: coloring for the layered model. `zhen` (fanzhen, warlords, circuits or factions) is the default; `pol` colors by state.
- `--flat`: fill each state flat in its own color without polity outlines, labeling each state at the label point of its largest area; for the Spring and Autumn and Warring States maps, as in their earlier thumbnails.
- `--blank`: draw only land, sea, rivers and the graticule, for a volume in preparation.
- `--en "id=English name;…"`: add or override English labels, as above.
- `--zh "id=Chinese name;…"`: override a Chinese label, for a short name (伪蒙疆 for 伪蒙疆联合委员会) or a different name: the map gives the CPC-held areas a collective name such as 中共（边区·根据地） or 中华苏维埃共和国, and the thumbnail names the area the label sits on instead, 陕甘苏区 (Shaanxi-Gansu Soviet Area) at 1937.07 and 陕甘宁边区 (Shaanxi-Gansu-Ningxia Border Region) at 1937.12.
- `--fs "id=size;…"`: set the size of a Chinese label (the English follows at 0.82 times); 0 leaves the label out, for a label hidden under the caption. For the Spring and Autumn and Warring States maps, use the state name, e.g. `--fs "淮夷=8"`: this keeps the label of a slightly small territory whose computed size is under 8 and would otherwise be dropped.
- `--inframe "id;…"`: units whose label point is moved inside the frame when it falls outside, as above; for the Spring and Autumn and Warring States maps, use state names.

The settings for the current nine:
