# 春秋列国形势图

[![中文](https://img.shields.io/badge/lang-%E4%B8%AD%E6%96%87-red.svg)](README.md) [![English](https://img.shields.io/badge/lang-English-blue.svg)](README.en.md)

春秋时期（前770—前476）的交互历史地图：46 个时间节点的列国疆域（以西周灭亡前一年前772 开篇），60 个诸侯国（周、晋、楚、齐、秦、鲁、宋、卫、郑、陈、蔡、曹、许、燕、吴、越，以及虢、虞、邢、纪、莒、邾、群舒、徐等小国）与 7 支戎狄部族（赤狄、白狄、山戎、西戎、伊洛之戎、大荔、淮夷），200 多处国都、城邑、关隘的古今地名对照，以及战役、会盟与文化事件、方城与齐长城、运河、山川、周边诸族。界面中英双语，地图右上角「中 | EN」切换。

本图与[战国列国形势图](https://jackyijun.github.io/zhanguo-map/)首尾相接：两图共用同一份归属点和同一张通行代价栅格，春秋末节点（前476）与战国首节点（前475）的疆域、配色逐像素一致。

## 三、本地构建

在单仓根目录构建（Python 版本与依赖见单仓 README）：

```bash
python run.py chunqiu  # 本卷第 1 段 → 统一引擎重算疆域（engine.json）→ v1 数据 → docs/chunqiu/index.html
python run.py --web    # 不重算，只由各卷的 source.json、engine.json 重建 v1 数据与新页面
```

本目录的 `run.py` 是第 1 段：由 `content/` 的史料与 `geodata/` 的底图写出 **`source.json`**（节点归属、文字、条目与底图，不含疆域与配色，入库），单仓由它转成 v1 数据。疆域由统一疆域引擎（单仓 `core/engine/`）按各节点的归属推算，结果存在本目录的 `engine.json`（入库）；颜色由单仓 `global/palette.toml` 定；页面由单仓 `core/web/` 生成。本卷原来的疆域推算、配色与页面模板 2026-11 架构整理第三批起退役。

| 命令（本目录） | 作用 |
|---|---|
| `python run.py` | 底图缺失则下载 → 底图与点要素归属（`build/geo.json`）→ 汇编 `source.json` |
| `python run.py --html` | 跳过底图与归属，只重新汇编（只改了 `content/features.py` 里的文字或 `content/en/` 的英文时用） |
| `python run.py --draft` | 英文有缺译或过期时也照样汇编（缺译处临时显示中文），只供预览；不加时构建会停下并列出缺译 |
| `python tools/i18n.py status` | 查英文缺译、过期的条数 |

改了 `content/` 以后，从单仓根目录 `python run.py chunqiu` 重建这一卷（第 1 段、疆域、页面一次做完）。只在本目录跑 `run.py` 不会更新 `engine.json` 和页面；归属变了而疆域没重算时，单仓 `python run.py --web` 发现引擎输入的指纹对不上，会停下。

同一份输入，`source.json` 逐字节一致，可以用 git 追踪改动。

底图数据（`geodata/ne/`）随仓库附带，离线也能构建；文件缺了，`run.py` 会从 GitHub 下载固定版本（Natural Earth v5.1.2）。

页面用的战国式旧模板在单仓 `core/web/old/chunqiu.html`（原是本卷的 `src/template.html`，2026-11 架构整理第三批移过去），由 `core/web/patch.py` 换上共用外壳；两卷改用统一模板另做一批。

## 五、工作原理

> 单仓新页面（`docs/chunqiu/`）的疆域，第 7 步（2026-11-19）起改由统一疆域引擎推算（`core/engine/`，结果在本目录的 `engine.json`，根目录 `python run.py chunqiu` 时自动重算）；归属、文字、条目仍出自本卷，归属点仍是与战国卷共用的 `content/seeds.txt`。外缘照旧构建的办法（`era.toml` 的 `[engine]` 写 `outer = "box"`）：推算范围同下面的栅格（97°—128.5°E、18°—44.5°N），范围内的陆地都分给最近的点（陆路够不着、离岸较远的岛留白，如台湾），不属任何一方的点占位之处留白；与旧构建不同的是代价按统一引擎的地形算，海不可通行，疆域不再画到海上。共主着色的「周天下」外缘取引擎政权层的「周」（王畿与奉周诸侯）。两卷共用归属点、代价与推算范围，春秋前476 与战国前475 的疆域逐字节相同。

```
content/seeds.txt ──┐
content/links.txt ──┤
content/features.py ┼─► build.py ─► build/geo.json ─► assemble.py ─► source.json ─► 单仓 core/：统一引擎疆域、v1、新页面
geodata/ (底图) ────┘                                    ▲
                                    content/features.py + content/en/
```

### 1. 为什么疆域要“算”出来

春秋没有现成的边界数据，史书能确定的大多是“某年某邑属某国”“某国灭某国”。所以这里只手写**地点 → 国家**的归属及其变化年份（`seeds.txt`），再用一张“通行代价”地图让计算机推出国与国之间的分界，让分界尽量落在山脊和大河上。

> 下面讲的疆域推算、配色与页面模板是本卷旧构建的做法，2026-11 架构整理第三批起已从本目录删去（第 1 段只出 `source.json`），留作说明旧版页面怎么来的。第 2 小节里的第 1、5 步（陆地、水系）与最后一步（地点归属）仍是第 1 段的做法。

### 2. 旧构建 `build.py` 的步骤

1. **陆地**：从 Natural Earth 裁出东亚陆地，简化后编码。
2. **代价栅格**：0.05° 一格。陆地代价 1，海 4.5；每条山脉按“阻隔权重”加代价，古黄河、济水、易水、北洛水和江、汉、漳也加代价；再叠一层固定随机种子的平滑噪声。这张栅格与战国图完全相同，原由 `config.py` 的 `COST_SHA` 每次核对。
3. **多源最短路**：从当年参与分区的归属点同时出发做 Dijkstra，每一格归给“走过去最近”的那个点。点集相同的节点只算一次。
4. **逐节点着色**：按 `seeds.txt` 查出每个点当年属哪国，把格子合并成各国范围，高斯平滑后描出轮廓并简化。注记位置取每国最大一块陆地的内部最远点。
5. **水系与湖泽**：Natural Earth 河流按英文名对到古名；黄河故道、济水、北洛水、伊洛、汝颍、泗水等手绘补上。
6. **地点归属**：每个城邑、关隘、战役点落在哪个归属点，写在 `content/links.txt`，带上那个点的归属变化，供提示框显示“某年属某国”。原先是查点落在哪个归属点的格子里；架构整理第三批（2026-11-20）起旧的分区格子不再参与，各点所落的归属点按当时查得的结果冻结在这张表里，新加的点要在表里写上（构建时检查）。2026-11-21 把按统一引擎的分区会落到别的归属点的 17 条逐条对过史料，改了其中 7 条（如虞的都城原落在下阳、算成属虢），另随战国卷改了中牟一条，说明写在文件开头。

### 3. `seeds.txt` 语法

每行一个点：

```
名称 经度 纬度 初始归属 [年份归属 ...] [^年份] [~年份]
```

- `·` 表示不属任何诸侯国（戎狄蛮夷之地，或空白）；部族也有自己的键（如 `赤狄`、`白狄`）。
- 年份用负数表示公元前，`-655晋` 表示前655 年起属晋。
- `~-350` 表示这个点从前350 起不再参与分区：为春秋小国、戎狄和战国早期补的点都带这个标记。此后参与分区的是原战国图的点，加上 2026-11 补的西北 4 个无主点、前280 起的下辨与前473 起的雍氏；退出的点所在的格子仍是描界时的护点，战国图前350 以后的界线与删去这些点时略有出入（约 0.1% 的面积）。
- `^年份` 表示这个点从这年起才参与分区，此前不参与。用到它的有两个点：`^-280` 的下辨（2026-11-21 补，秦陇西郡属县，随陇西郡置算入秦；补它时核对过，前280 以前的疆域逐字节不变），`^-473` 的雍氏（见下一条；从前473 起是为了不动春秋卷与前475 衔接节点）。
- 文件末尾一节是 2026-11-21 为提示框与地图对上补的 9 个点（不羹、期思、桃林、河曲、应、酅、南武城、寝丘、雍氏）：这些城邑、关隘提示框里的归属合史料，地图却因描界平滑或旁边的点把它画进了邻国。在条目处补一个归属与提示框相同的点，地图随之画对（桃林塞的点挪到黄河南岸，另在北岸补河曲一点，让虢、晋的界线贴着黄河）。桃林塞（原作古魏、前661 入晋）、寝丘（原随新蔡）的提示框归属也一并按史料改正；补点的地方疆域变了几十到一千多平方公里。

例：

```
陕 111.2 34.76 虢 -655晋 -453魏 -324秦
潞 113.2 36.1 赤狄 -594晋 -453韩 -262赵 -260秦 -257赵 -247秦
下阳 111.3 34.83 虢 -658晋 -453魏 ~-350
许叶 113.52 33.58 申 -688楚 -576许 -533楚 -529许 -524楚 -506许 -390楚 ~-350
```

### 4. 与战国图的衔接

- 两卷的 `content/seeds.txt` 完全相同；统一引擎按同一份归属点、同一张代价栅格、同一推算范围推算两卷的疆域（旧构建时山脉、手绘界河的几何与阻隔权重也须相同，由 `COST_SHA` 校验）。
- 任何一行都不在前475 这一年变更归属，所以春秋图前476 与战国图前475 用的是同一组点、同一张栅格、同一份归属，算出的疆域多边形和国名位置逐字节一致。
- 两图共有的国家（秦、楚、齐、晋、郑、吴、越等 28 个）同键同色：颜色按政权全局 ID 定在单仓的 `global/palette.toml`。
- 衔接以「诸侯」着色为准。「共主」着色只有春秋图有，战国图不做。
- 改其中一张图的 `seeds.txt` 或山脉、界河时，另一张图要同步修改并一起重建。

### 5. `features.py` 里有什么

| 名称 | 内容 |
|---|---|
| `STATES` | 67 个政权与部族的姓氏、介绍（疆域色在单仓的 `global/palette.toml`） |
| `STATE_KIND` · `STATE_ALIAS` | 戎狄部族（淡色虚线、不计入国数）；当年别名（前506 以前中山注记为“鲜虞”，前638 起伊洛之戎注记为“陆浑之戎”） |
| `ALLEGIANCE` | 共主着色：哪些国自立、从哪年起，附依据（楚前704 称王、前671 献天子受胙、前606 问鼎；吴前585 称王；越、蜀等不在周的封建之内，徐君称王）。未列出的诸侯一律奉周 |
| `SNAPS` · `SNAP_SHORT` | 46 个时间节点（前772 为开篇节点）：年份、标题、一段概述；时间轴上竖排的短名 |
| `FIRST` · `PERIOD0` · `PLAY_MS` | 首屏节点（前632）、第一个节点“本期”的起算年（前781 幽王即位）、播放间隔 |
| `CAPITALS` | 91 处国都，含起止年份（迁都后旧都显示为虚线框） |
| `BATTLES` | 64 场战役：年份、胜负、主将、经过 |
| `PASSES` · `CITIES` · `TOWNS` | 关隘津渡、名城要邑、一般城邑 |
| `CULTURE` | 48 处事件、会盟、人物与考古遗址 |
| `WALLS` · `RANGES` | 楚方城、齐长城；24 条山脉 |
| `NE_RIVERS` · `MANUAL_RIVERS` · `CANALS` · `MARSHES` · `NE_LAKES` · `LAKE_NOTES` · `RIV_OVERRIDE` | 水系古名、手绘河道、运河（邗沟、菏水，按开凿年份出现）、古泽薮、湖泊 |
| `PEOPLES` | 20 处周边诸族注记，按存续年份显示 |
| `FALLS` | 年表里的灭国条目：年份、亡国名、经过 |

### 6. 页面显示规则（`core/web/old/chunqiu.html`）

- 战役只显示**本期**的，即上一个节点之后（不含）到本节点（含）发生的；说明栏末尾列出“本期战役”，点击即定位。
- 事件、长城、运河只显示到当前节点为止已经发生的；国都只显示当时的国都和已废的旧都。
- 戎狄部族的疆域淡色、虚线边，注记斜体，不计入顶栏的国数。
- 图例只列本期尚存的政权和本期新亡的政权（划掉），部族排在最后。
- 缩放分级：全图只显示国名、国都、战役；放大后才出现关隘、名城、一般城邑和今名。
- 着色有两种，顶栏切换：**诸侯**（各国本色，默认）与**共主**。共主着色下，周王畿为周色；受周封爵、未称王的诸侯为奉周，用周色浅填加斜线，名义属周、实各自治；称王或不在周的封建之内者为自立，用本色；楚称王后曾向周王进贡受赐，前671—前607 也算奉周；戎狄部族不变。王畿与奉周诸侯合成的「周天下」外缘画一条粗线。
- 视野用下拉框切换（全域、中原、晋秦、齐鲁、江汉、吴越）。

## 七、英文版

页面里有中、英两种界面，默认中文；地图右上角「中 | EN」切换，选择记在浏览器里，网址加 `#en` 直接打开英文。英文模式下地图只标英文，悬停说明、索引、年表、对照表在英文名后附小号汉字原名；检索同时收中英文，英文不分大小写。

- **中文是源文本。** 英文按“文件 · 键 · 字段”另存在 `content/en/`：条目键为 `类别:古名`（同类同名的第二条起加 `#2`），节点键为年份，今省名为 `prov:省名`，灭国条目为 `fall:年份`，当年别名为 `alias:键:别名`。
- **指纹。** `zh.lock.json` 记下每条英文所据中文的 sha1 前 10 位。中文一改，对应英文就算“过期”；`assemble.py` 默认严格，有缺译或过期就停下，`--draft` 才放行。
- **工具。** `python tools/i18n.py status` 看缺译、过期条数；`todo` 导出待译中文；`table` 导出中英对照表 `build/i18n_table.csv`；`lock` 登记指纹。
- **译名体例**见 `content/en/GLOSSARY.md`，与战国图体例一致，两图同名同译。

## 八、调参

疆域的推算参数不在本卷：统一引擎的通用参数在单仓 `core/engine/config.toml`，本卷的外缘、推算范围、简化容差等写在 `era.toml` 的 `[engine]`；颜色在单仓 `global/palette.toml`。本卷原来的栅格、代价、平滑与配色参数 2026-11 架构整理第三批起随旧构建一并退役。

两卷共用归属点与推算范围（`era.toml` 的 `[engine]` 写 `outer = "box"`），改推算参数时两卷要一起重建，春秋前476 与战国前475 的疆域才一致。原来 `src/config.py` 里的栅格、代价、噪声参数和代价栅格校验值 `COST_SHA` 随旧构建退役，`src/config.py` 只剩路径、底图来源与范围。

## 九、资料与可靠程度

- **疆域归属**：依据《左传》《史记》《国语》《竹书纪年》等史料与谭其骧《中国历史地图集》第一册春秋图的大意推定，由 AI 协助编写，未逐条核对原文。大的格局和关键年份（如前655 晋灭虢虞、前632 城濮、前597 邲、前567 齐灭莱、前506 吴入郢、前487 宋灭曹、前478 楚灭陈）比较可靠；早期诸国的范围、边缘地区（戎狄、群舒、江南、巴蜀）较粗略。
- **边界线**：完全是推算的示意线，只表示“这一带属于这个国家”。
- **小国与戎狄**：春秋诸侯百余，图上只画出六十个；不单独画出的小国（如温、原、应、蒋、宿、颛臾）并入邻近大国。戎狄的分布多据《左传》零星记载示意。
- **有争议处**：地图里注明“一说”“地望有争议”，如楚都丹阳、故绛、邾早期都城、杞的东迁路线；楚早期疆域兼取丹淅、荆睢两说。随（曾）、许的灭亡年代史无明文，图上分别示意为约前360、约前390。
