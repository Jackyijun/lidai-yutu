# core/engine：统一疆域引擎（第 5 步）

八卷原来用了四套疆域引擎（规范第十三节）。这里把它们合成一套：以两晋、隋唐那套为底（投影平面上的等距格子、16 邻接多源最短路、两侧共用的界线），并入宋元、民国的可达代价外缘、闭运算与国界墙。

第 5 步时只**陪跑**：由 v1 数据重算疆域，逐节点与现有页面比对，页面不变。第 7 步起各卷逐个换过来（见下「第 7 步：旧卷换到引擎」），隋唐、两晋（2026-11-17），宋元、民国、唐宋（2026-11-18），汉末、春秋、战国（2026-11-19）先后换完，八卷都已由引擎出疆域。

第 6 步新编的秦汉卷是第一个**直接由引擎出图**的卷（`era.toml` 的 `[engine]` 写 `production = true`）：本卷构建先出一遍没有几何的归属，转成 v1，`python core/engine/build.py qinhan` 推算各节点的郡国疆域，写到仓库根目录的 `build/engine/qinhan.json`，本卷再构建一遍填进去、写成 `source.json`。根目录 `python run.py` 自动走这两遍。

第 7 步起旧卷也逐个换过来：`era.toml` 的 `[engine]` 写 `geometry = "engine"`（秦汉以外的八卷都已写上），见下「第 7 步：旧卷换到引擎」。

```
python run.py suitang                        构建一卷：第 1 段 → v1（先不带疆域）→ 引擎推算 → eras/suitang/engine.json → v1 → 新页面
python core/engine/build.py suitang          只推算：build/engine/<短名>.json（几何池 + 各节点 u / ul / pu / pul；唐宋、宋元另有 regions）；要先有 build/v1/<短名>.json
```

`build/engine/` 不入库。推算结果与库版本有关，和各卷原来的构建一样；要与别人的结果逐字节对上，用 `requirements-lock.txt` 那组版本。

## 一张全球格网

格网铺在统一投影（`core/geo/config.toml`）的平面上，格边长 1.1 个投影单位（约 7 km）。第 (i, j) 格的格心在 x = (i + ½) · 格边长、y = (j + ½) · 格边长，与卷无关。各卷只取覆盖自己外缘的一个矩形窗口来算。

代价栅格里只由位置决定的部分（陆地、地形、山地、山脊、随机扰动）在任何窗口里都逐位相同：

- 随机扰动（代价噪声、界线的位移场）按 256 × 256 格分块生成白噪声，每块的种子只由全局种子、场的编号和块号决定；高斯平滑时多取一圈边距，再按卷积核算出的理论标准差归一化，不按窗口里的样本归一化。
- 地形、山脊、界河的平滑与距离变换也都多算一圈边距再裁回。
- 最后把代价舍入到 10⁻⁶，抹掉浮点运算顺序带来的 10⁻¹² 量级尾差。

所以同一个地方在哪一卷代价都一样，相邻两卷可以共用归属点。

## 代价

代价 =（1 + 地形起伏 + 高海拔 + 山地 + 山脊带 + 界河 + 国界墙）×（1 ± 噪声）。参数都在 `config.toml`。

| 项 | 来源 | 做法 |
| --- | --- | --- |
| 地形起伏、高海拔 | ETOPO20 | 3 × 3 窗口内高差每千米 +1.1（上限 3 千米）；2500 m 以上每千米 +0.9（上限 3 千米） |
| 山地 | Natural Earth 山地多边形 | 整体 +1.2，高斯模糊 3 格 |
| 山脊带 | 全局山川表的山脉 | 每条山脉取一种画法：`global/decisions.toml` 的 `[physical.prefer]` 定了的按决定，其余取画法相同的卷最多的一种；主干峰值 8、次要 3.5，高斯带宽 10 km；按名字定相位横向摆动 |
| 界河 | 本卷画的河道 | 黄河、淮河历代改道，所以河道取节点所在时代那一卷画的；长江 5、黄河 5、淮河 4、多瑙河 4……共 29 条，见 `config.toml` |
| 大湖 | 本卷画的湖 | 0.15 平方度以上不可通行 |
| 国界墙 | Natural Earth 今国界 + 各卷手画的界线 | 民国式：峰值 60、半宽 14 km；今中国省界为弱墙；归属点周围 8 km 内不烧墙、到 22 km 恢复全强度；有时效的墙按节点所在月份启用，每组墙各跑一次最短路 |

地形项取宋元式，没有用隋唐式的坡度与高原：按可达代价定外缘的卷对地形项最敏感，坡度项在横断山一类陡峭山地代价过高，宋元卷的川西外缘会缩回去。拿隋唐、宋元两卷试过五种组合，这一组两卷合计差别最小。

## 输入：点 → 单位 → 政权

引擎只认一种输入（`data.py` 的 `view()`）：每个节点上每个归属点归哪个单位，每个单位属哪个政权，以及哪些点参与分区。九卷都取 v1 的 `places`（归属点）与各节点的 `own`、`pol`；归属点写了 `t1` 的，此后的节点不参与分区。

- 春秋、战国的归属点是两卷共用的 `content/seeds.txt`（归属沿革、`~年份` 退出分区），生成 v1 时转成 `places` 与各节点的 `own`。单位是诸侯国；春秋的政权层是共主，奉周的诸侯归「周」，政权层「周」的外缘就是共主着色的「周天下」。这两卷原是另一种简单写法，引擎读入时另行合成；2026-11-20 v1 本身改成这一种（架构整理第 2 批），引擎输入换算回国名后与原来逐项相同，疆域几何也相同（只有个别环的起点与顺序不同：引擎按单位编号排序描界，编号由国名改成了序号）。
- 春秋、战国的单位注记 `ul` 照旧页面的写法（era.toml `[engine]` 写 `labels = "zhanguo"`）：每个单位一组 `[[经, 纬, 面积, 半径], …]`，取陆上最大的一块，另加不小于 max(40 格, 最大块 30%) 的飞地，最多 3 处；面积按 0.05° 见方的格数计（页面按它定国名字号）。别的卷是单个 `[经, 纬, 平方度, 半径]`。

## 分区、外缘与描界

1. **分区**：以本卷全部归属点为源，跑一次 16 邻接多源最短路，每格归代价距离最近的点。落在海里的点就近挪到陆地，两点同格的挪到旁边一格。有点退出分区的卷（春秋、战国，归属点写了 `t1`），每组参与分区的点各跑一次。
2. **外缘**：由各卷 `era.toml` 的 `[engine]` 定。
   - `outer = "frontier"`（隋唐、两晋）：手绘外缘，读 `content/frontier.py`，栅格只建在外缘以内。
   - `outer = "box"`（春秋、战国）：推算范围 `box` 以内的陆地全分给代价最近的点，不按可达代价截断；外缘由不属任何一方的点（seeds.txt 里写 `·` 的戎狄蛮夷之地）撑出来，同旧构建。够不着的海岛离有主地 6 格以内的并入，再远的留白（台湾）。
   - `outer = "reach"`（汉末、唐宋、宋元、民国）：超出该点可达代价（默认 130，`seeds` 文件里可写 `R=倍数`）的格子为无主地；外缘先闭运算（半径 12 格），小于 600 格的无主空隙并回相邻一方，再高斯平滑（平滑时把海面当作有主，海岛、半岛尖不被磨掉）。并回的空隙、平滑出来的有主地只认离有主地 12 格（约 85 km）以内的：否则远洋小岛、推算范围边上切下的碎块也会被平滑成有主，归给隔海最近的政权（2026-11-19 查出：宋元卷的马里亚纳归了日本、安达曼归了蒲甘，汉末卷换引擎时日本、吕宋冒出汉的边线）。民国卷写 `far_islands = true` 照旧：殖民地、委任统治地的群岛多没有归属点，远洋小岛仍并入最近的一方。推算范围是 `box`，减去设置文件里的 `EXCLUDE`。
   - 疆域向海面延伸 6 格，页面按陆地裁剪。
3. **描界**：每个节点按「点 → 单位」把格子分类，每类作高斯平滑，界线描在相邻两类平滑值相等处。界线网络全图只描一次、两侧共用，再做三轮拉普拉斯平滑，相邻疆域之间没有白缝或叠色。之后加位移场，整体覆盖简化。单位之并即政权：政权有两个以上单位，或唯一的单位不是政权自己，另出一层。
   - 二级区划（`[engine]` 的 `zones`，汉末卷的州）：这个文件的 `zone_of(点键, 年, 单位键, 政权键, 单位种类)` 给出各点在这一节点所在的区划块，格子按「单位 × 区划块」分类描界，描完再按单位合并；区划块之间的共享边（不含外缘）就是区划界，写进节点的 `zb`，面积大于 `zone_label_min`（平方度）的区划另出名字锚点 `zl`。区划界与单位界是同一批边，重合处严丝合缝。
   - 细分（`[engine]` 的 `sub`，战国卷的秦郡）：这个文件的 `UNIT` 是被细分的单位，`HOSTS` 是治所须落在其疆域里的单位，`NEAR` 是容差（格），`seats()` 给出 `[(块键, 经, 纬, 始置年)]`。每个节点里已始置、治所落在 HOSTS 疆域以内（或离它不到 NEAR 格）的治所，在同一张代价图上再跑一次多源最短路，`UNIT` 的格子按就近的治所分块，按「单位 × 块」描界，再按单位合并；各块的多边形写进节点的 `zp`，注记写进 `zpl`。与 `zones` 不同，块按格子分、不按归属点分，所以块界不跟着归属点的势力格走（同旧构建的秦郡）。
4. **归属点护格**：旧引擎偶尔把点划到对方境内（四卷合计约 1500 个节点次），这里加了三道保护。
   - 平滑后，点所在格及其紧邻的同类格仍归本类，含点的小块不并入邻居。
   - 位移场挪动界线时，挪动后的界线离任何归属点都不得近于 1 格。
   - 仍不在本方疆域内的点，补一个半径 0.6 格的小圆，从别的单位里扣掉（民国卷的赛迪尔巴希尔在推算范围边上、亚喀巴在国界墙交汇处）。离本方界线不到 0.01° 的点，再按页面的坐标精度（经纬度 0.01°）取整后查一遍（同一单位的区划块合起来查），取整后压在界线上或落到界外的也补：多是界河岸边的点，界线本来就贴着河走（战国卷的内黄、汉末卷的白马；2026-11-19 加这一查，其余已换的卷重算后逐字节不变）。
   - 新引擎下四卷每个节点的点都在本方疆域里，只有手绘外缘以外的点除外（隋唐、两晋的「鄂毕上游」，旧版也一样）。

## 第 5 步的比对结果（2026-11-15）

| 卷 | 节点 | 陆地归属变化：全卷（每节点） | 点不在本方疆域内：新 / 旧（节点次，外缘以外的不算） | 陆上直线段最长：新 / 旧 |
| --- | --- | --- | --- | --- |
| 两晋 | 122 | 6.9%（5.4%—10.5%） | 0 / 40 | 27 km / 101 km |
| 隋唐 | 26 | 5.6%（4.4%—6.5%） | 0 / 5 | 26 km / 33 km |
| 宋元 | 62 | 9.8%（8.6%—11.5%） | 0 / 500 | 33 km / 91 km |
| 民国 | 115 | 2.5%（1.3%—3.8%） | 0 / 986 | 36 km / 90 km |

- 变化多在归属点稀疏的地方（塔里木、青藏边缘诸部、洱海、林邑等），那里界线主要由地形和随机扰动决定；宋元、民国另有按可达代价定的外缘。民国卷有国界墙，变化最小。
- 两晋 10.5% 的是 280 年节点：旧版照搬汉末三国的几何（经纬格、8 邻接），新引擎按本卷归属点重算。
- 覆盖图在陆地上都有效（没有白缝、叠色）；两晋卷 30 个节点在爪哇岛东端以南的海面上有一段约 6 km 的细缝，页面按陆地裁剪，看不到。

## 第 7 步：旧卷换到引擎

各卷的第 1 段构建（各卷自己的 `run.py`）出归属、文字与条目，存为 `source.json`（架构整理第三批起只出这些，旧构建的疆域推算已删去）；疆域由引擎出：

1. `python run.py <短名>` 构建这一卷时，先由刚出的 source.json 生成 v1（`core/v1/build.py --lenient`：这一遍还不带疆域），引擎按 v1 的归属推算，结果复制为 `eras/<短名>/engine.json`（入库）；
2. 生成 v1 时（`core/v1/engine_geom.py`），各节点的几何 u / ul / pu / pul 换成 engine.json 里的。engine.json 入库，所以 `python run.py --web` 不必重算疆域，结果也与库版本无关；
3. engine.json 记着引擎输入的指纹（`data.py` 的 `fingerprint()`：归属点、各节点「点 → 单位 → 政权」、`config.toml`、era.toml 的 `[engine]`、手绘外缘文件，写了 `zones` 的卷另加区划规则文件与各点的区划块，写了 `sub` 的卷另加治所表，有重要地域的卷另加地域与各分区的成员点、画不画分界线）。归属改了而没重算，`core/v1/build.py` 与 `python run.py --check` 都会报出来。山脉、界河、陆地等全局底图与引擎的代码不计在指纹里，改了要手动重算这几卷（删掉 `eras/<短名>/engine.json` 再 `python run.py <短名>`）；
4. 衔接节点按 `global/junctions.toml`：本卷为准的照用本卷引擎的结果；对方为准、对方也已换到引擎的，在对方的推算范围（手绘外缘，或按可达代价定外缘的卷的 `box`）以内照搬对方引擎的几何，只画到本卷的推算范围，以外用本卷的，跨线的同一单位两部分合并。对方的单位依次按同键、同全局 ID（`global/polities.jsonl`）、所属政权（对方政权层几何过半落在哪个本卷单位）对上本卷的单位，对不上的那块用本卷自己的几何；对方没有的单位（对方留白处，如汉末卷 280 年没画的天竺、苏毗、骠国、扶南、倭）照本卷画；对方的 engine.json 缺了，`--lenient` 那一遍先用本卷自己的几何，正式生成 v1 时停下。两晋卷 581 年照搬隋唐（两卷在隋唐外缘以内一致），280 年照搬汉末卷；唐宋卷 979 年照搬宋元。秦汉卷不走这一条（它本来就由引擎出图）：两端由它自己的构建照搬（`eras/qinhan/src/build.py` 的 `zg_engine_212`、`hm_engine_184` 读战国卷、汉末卷的 engine.json），所以 `run.py` 先重算已换卷的 engine.json，再做秦汉卷的第二遍构建；
5. 春秋、战国同上一并换（春秋的周天下就是政权层「周」）；战国卷的秦郡界（节点 `ext` 的 `j`）另取引擎的细分块 `zp`。
6. 重要地域（唐宋、宋元的燕云十六州，v1 `base.regions`）也由引擎描（架构整理第三批，2026-11-20）：取地域起始年那个节点的分区，成员点（`m`，含雄州、霸州）的格子之并描出范围线；各分区（山前七州、山后九州、瀛莫）再与地域其余部分描一次，得分区注记，写了 `line` 的另出两者之间的分界线（山前、山后之间）。注记的取法同疆域（陆上最大一块的内部最远点）；分区注记离地域总名不足 1.2° 的，改取避开总名的那一点（同旧构建）。结果在 engine.json 的 `regions`，生成 v1 时填进去（第 1 段只给成员点，旧构建用栅格描的范围线、分界线和注记已随旧构建删去）。范围线因此与页面上的疆域边界重合（旧构建的那条与引擎画的宋、北汉、辽疆界错开）。

换引擎时（2026-11-17）的变化见下表「第 5 步的比对结果」的两晋、隋唐两行：陆地归属变化 6.9%、5.6%，多在归属点稀疏处。第二批宋元、民国（2026-11-18）陆地归属变化 9.8%、2.5%，点都在本方疆域里（旧版合计约 1500 个节点次不在）。这两卷视野大、节点多，照 `[trace]` 的默认容差 0.06 格出图，疆域几何约翻倍（民国卷页面 21 MB，超出 artifact 上限），所以在 era.toml 的 `[engine]` 写 `simplify = 0.25`（约 1.8 km），页面体积与旧版相当；平时看图的比例下与默认值看不出差别，放大到县一级才看得出平缓长弧上的折线。宋元卷 999 年花剌子模（马蒙王朝）原来按可达代价把乌斯秋尔特高原、卡拉库姆沙漠大片划入，给玉龙杰赤、希瓦两点写了 `R=0.2`，只留阿姆河下游绿洲。第三批唐宋卷（2026-11-18）陆地归属变化 10.8%（各节点 9.8%—11.6%），点都在本方疆域里（旧版也都在）；旧引擎的界线是折线，每节点平均 1529 段长于 20 km 的直线、最长 273 km，新版平均 21 段、最长 36 km。唐宋卷照默认容差 0.06 格出图：折点约为旧版的七倍，页面由 2.7 MB 增到 5.9 MB（gzip 后 1.0 → 1.9 MB），离上限还远，没有放宽。阿里一线（羊同与定日之间七百多公里）原来没有归属点，玛旁雍错到雅鲁藏布江上游留成白地，唐宋、宋元两卷各补了普兰、仲巴两个区域辅助点；羌塘北部（可可西里）没有聚落，照大流沙的道理留白。第四批汉末卷（2026-11-19）陆地归属变化 12.7%（各节点 11.5%—14.1%），多在夫余、高句丽、林邑、鲜卑、诸羌的外缘与中原诸侯之间；旧版每节点有一两个点不在本方疆域内（合计 35 节点次），新版没有；陆上长于 20 km 的直线由每节点约 300 段、最长 101 km 降到约 1 段、最长 23 km。州界由引擎按「诸侯 × 州」分块出（`zones = "src/zhou.py"`，原构建定州的规则搬到这个文件）。可达倍数由旧版各点的分区半径（度）折算，`src/build.py` 写出 `build/reach.txt`：旧算法的可达距离是「半径 × 1.45」个代价·度，1° 约 17.45 投影单位，两套代价的尺度不同，照字面折算外缘缩进去一成多，试过 1、1.5、2 三档系数（归属变化 16.1%、12.9%、17.9%），取全卷有主陆地面积与旧版最接近的 1.5；带方一点再乘 0.5，免得越过汉江覆盖三韩。远洋小岛的修正（上文「外缘」）同批做，唐宋、宋元、秦汉三卷随之重算，变化都在远处小岛（唐宋 0.28%、宋元 0.53%、秦汉约 1.5%）；唐宋、宋元两卷补郁陵岛一点。衔接：秦汉卷 184 年照搬汉末卷 engine.json 的政权外廓，两晋卷 280 年在汉末卷的推算范围内照搬它的引擎几何。另有一处画法上的统一：塔里木盆地中央的「大流沙」「罗布」等无主参考点，旧引擎在前 649 年以前把它们周围的沙漠分给焉耆、龟兹，新引擎各节点一律留白。

第五批春秋、战国（2026-11-19）：`outer = "box"`，推算范围同旧构建的栅格（97°—128.5°E、18°—44.5°N），两卷相同；旧引擎海可通行（代价 4.5）、平地代价处处一样，引擎按地形算、海不通行。陆地归属变化 12.1%（各节点 9.7%—14.6%）、7.1%（4.0%—10.1%），多在巴、蜀、义渠、西戎这些山地国家的边缘（界线改贴山脊）与中原小国之间；疆域不再画到海上（旧版战国末节点的秦盖住台湾、琉球、吕宋北端，春秋末的越盖到冲绳附近）；旧版合计 16 个节点次的点不在本方疆域内，新版没有。前476 / 前475 两卷共用归属点、代价与推算范围，28 国逐字节相同。秦郡由引擎细分（`sub = "src/jun.py"`，郡治表取 `content/features.py` 的 `JUN`），`NEAR = 4`：洞庭郡治在秦、楚交界上，新分区把那一格分给了楚的临沅，不放宽会在前277—前223 整个消失；副作用是河东郡在前290 年提前一期出现（治所安邑那年还属魏，四周已属秦）。两卷共用的 `seeds.txt` 在西北补武威、张掖、阿拉善、居延 4 个无主点：前215 年后贺兰、景泰、兰州归秦，西北再无别的点，按地形算河西走廊与阿拉善会整片归秦，铺到推算范围边上；补点后秦的西北界大致在贺兰山—黄河一线，只有前212 一个节点变。两卷写 `simplify = 0.25`：默认 0.06 格时页面大七成（1.8 → 3.1 MB、1.5 → 2.6 MB），放宽后 2.3、2.0 MB；代价是缓弯拉成弦，陆上长于 20 km 的「直线」每节点仍有一两百段（最长 59 km，离原曲线不到 1.8 km），旧版的长直线（最长 186 km；战国末节点画在海上的秦疆外缘有 1442 km）没有了。

## 比对（原 regress.py，已退役）

第 5—7 步换引擎时，`regress.py`（`python run.py --engine`）逐节点与当时的页面（旧引擎画的几何）比对四样，上文各卷的变化比例就是它报的。八卷都换完、旧构建退役后（架构整理第三批，2026-11），它与 `--engine` 一并删去。比的四样：

1. 点：每个归属点是否落在本方疆域内，新旧各查一遍；
2. 面：陆地上新旧归属不同的面积占比，逐节点、逐单位；
3. 线：陆上长于 20 km 的直线段，新旧各数一遍；
4. 缝：覆盖图是否有效（相邻疆域之间有没有白缝、叠色）。

## 文件

| 文件 | 内容 |
| --- | --- |
| `config.toml` | 全部参数；试参数时可用环境变量 `ENGINE_CONFIG` 指向另一份、`ENGINE_OUT` 指向另一个输出文件夹 |
| `grid.py` | 全球格网、按块生成的随机场 |
| `data.py` | 输入：v1 数据包、全局山脉、陆地、各卷的外缘与国界墙设置 |
| `cost.py` | 代价栅格 |
| `partition.py` | 多源最短路、可达代价外缘、向海面延伸 |
| `border.py` | 描界、位移场 |
| `build.py` | 一卷的推算 |

各卷的外缘、国界墙、区划规则还读各卷自己的文件（`content/frontier.py`、`src/config.py`、seeds 文件里的 `R=`、汉末卷的 `src/zhou.py`、战国卷的 `src/jun.py`）。原计划第 7 步各卷换过来时挪进 v1 数据或全局表，换完时没有挪。
